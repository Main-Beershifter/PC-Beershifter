# Task-triggered saving and recall

Version 1.0 — adapted for PC Secretary on 2026-09-17.

## Start a substantive task

1. Check the public PC repository's actual default branch and latest commit once. Compare against the last verified task checkpoint.
2. If the commit is unchanged and the applicable files are already loaded, reuse them. If changed, inspect changed paths and reopen affected guidance and task-relevant records. For a new context or unavailable comparison, load the minimum governing files directly.
3. Report UNVERIFIED when access fails. Do not assume cached content is current or claim another agent received a handoff.
4. Read the current state, applicable user decisions, and relevant inventory/source entries. Treat the trading handshake as a dated reference, not a requirement to keep rereading the trading repository.

## Save at meaningful boundaries

Preserve completed reusable findings, user decisions, material corrections, blockers, and a concise next step. Avoid storing every message or generating empty commits. For an unfinished task, record a sanitized checkpoint with actual completion stage and outstanding approvals; do not represent a draft as validated research.

Before publication: inspect the exact file list and diff; check source identity, dates, uncertainty, copyright and sensitivity; validate internal links/inventory consistency where relevant. Use the branch/review workflow in AGENTS.md. Verify the resulting default-branch commit and changed contents. Preserve the last verified commit in a task handoff; do not try to embed a commit's own SHA inside itself.

## Resume interrupted work

Reconcile planned, attempted, locally saved, validated, committed, merged, and remote-verified stages. Preserve unrelated edits. Resume still-authorized safe work from actual state, not a previous success claim. Retry an availability failure only when circumstances support a safe retry; do not bypass a permission or policy rejection.

If publication is blocked, record the safe completed work, pending destination, blocker category, next action, and approvals required. Tell the user what remains incomplete. A local commit is not a successful GitHub save.

## Compact handoff

Include repository, branch, verified commit, check time, changed paths, artifact status, source cutoff, unresolved uncertainty, and receiver action. Share only with an authorized accessible recipient when needed. No full transcripts or unrelated project data.

Repository freshness and research freshness are separate: a recent save does not refresh a price, specification, warranty, release, or compatibility finding. Reopen time-sensitive sources before relying on them for a new decision.

This is an active-task workflow, not a background process. No heartbeat or scheduled search has been established.
